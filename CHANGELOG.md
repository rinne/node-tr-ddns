# Changelog

## Unreleased

Work towards 2.0.0. Nothing in this section has been published.

### Added

- A test suite built on `node:test`, run with `npm test`. It covers the
  name database, the DNS server over UDP and TCP, the HTTP API, the
  command line program and the contents of the npm package.
- `close()` on `NameDB` and `ApiServer`. `NameServer.close()` returns a
  promise.
- An allowlist of published files in `package.json`.
- A lockfile and a CI workflow.

### Changed

- Repository layout: the library is in `lib/`, the program is
  `bin/tr-ddns`. A launcher stays at the old `./tr-ddns` path.
  `require('tr-ddns')` and the old deep paths such as
  `require('tr-ddns/namedb')` keep working through the `exports` map;
  other files of the package can no longer be required.
- `package.json` has a `bin` entry, so installing the package provides the
  `tr-ddns` command.
- `README.MD` is now `README.md`.
- `tr-apisrv` 0.2.0 to 3.0.0 and `optist` 2.0.1 to 3.0.0.
- Errors generated by the HTTP layer itself (unsupported method, unreadable
  body, read timeout) are now JSON in the same `{ status, code, message }`
  envelope as all other API errors. They used to be `text/plain`.
- A request path with an empty segment or a dot segment (`//`, `/.`, `/..`)
  is answered with 400 instead of 404.
- A request body larger than 1 MiB is refused with 413.
- Command line usage errors are printed to the standard error.

- Node.js 24 or newer is required.
- A query for a name inside a served domain is answered whatever the query
  type is, with an empty answer when there is no data. Types that the
  server did not know, such as HTTPS (65), used to get no answer at all,
  which made clients wait for a timeout.
- A name inside a served domain that is not a valid host name gets an
  NXDOMAIN answer instead of no answer.
- Packets that are not plain queries are ignored: responses, operations
  other than QUERY, and packets that do not have exactly one question.
- A DNS listener that cannot be started makes `NameServer` emit `error`,
  and the program exits with status 1. The failure used to be silent.
- A missing configuration file is reported as missing.

### Fixed

- MX records were never returned.
- `merge=true` copied the TXT values of a host into its MX records.
- A TXT value longer than 255 bytes produced a malformed DNS response.
- `/record` with an invalid value answered 400 but still rewrote the host
  and then failed while sending a second response.
- `/record` made an expiring host permanent.
- `/host` with `remove=true` and `mx` is refused like the other
  conflicting combinations.
- Debug output of the whole database on every configuration write, and of
  the host on every `/record` call.
- The examples in the README.
- A query over TCP that gets no answer no longer leaves the connection
  open until the idle timeout; the connection is closed.

## 1.1.1 (2025-05-12)

- Optional HTTP Basic authentication for the API (`--http-api-user`,
  `--http-api-password`).

## 1.1.0 (2025-05-10)

- A host can have several A, AAAA, TXT and MX records. The new `/record`
  API call adds, sets, removes and clears single values.

## 1.0.10 (2025-05-10)

- A host name may start with an underscore.

## 1.0.1 to 1.0.9 (2025-04-06 to 2025-04-07)

- MX records and simplified domain handling.
- `merge` parameter for `/host`.
- Synthesised NS and SOA records for served domains.
- Logging, and less frequent writes of the configuration file.
- Queries for names outside the served domains get no answer.
- `/stats` API call.
- Fixes to host and domain name validation.

## 1.0.0 (2025-04-06)

- Initial release.
