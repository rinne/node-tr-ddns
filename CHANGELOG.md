# Changelog

## Unreleased

Work towards 2.0.0. Nothing in this section has been published.

### Added

- A test suite built on `node:test`, run with `npm test`. It covers the
  name database, the DNS server over UDP and TCP, the HTTP API, the
  command line program and the contents of the npm package.
- `close()` on `NameDB` and `ApiServer`. `NameServer.close()` returns a
  promise.
- An allowlist of published files in `package.json`.
- A lockfile and a CI workflow.
- Rate limiting of DNS queries per source address (per /64 prefix for
  IPv6): 500 queries per second by default, set with `--dns-rate-limit`
  or the `rateLimit` option of `NameServer`, 0 for no limit. Queries over
  the limit are ignored.
- `--http-api-password-file` reads the API password from a file.
- `--config-write-interval` sets the shortest time between two writes of
  the configuration file.
- On SIGTERM and SIGINT the pending changes are written to the
  configuration file and the program exits with status 0.
- A warning at startup when the API listens on an address other than
  loopback without authentication.
- `/host` accepts several values for a record type, as a repeated
  parameter or a JSON array.
- `/stats` reports `authFailures` and, under `dns`, counters of queries
  received, answered and dropped by reason.
- `ConfigStore`, exported from the library: loads a configuration file
  into a `NameDB` and saves it on changes.
- `NameServer.stats()`, `NameDB.lookup()`, `NameDB.getHostExpires()`, an
  `options.serial` argument for `NameDB.addDomain()`, and `ready` and
  `error` events on `ApiServer`.
- The test suite enforces a coverage threshold.
- Record types CNAME, SRV and CAA, and NS records on a host, which
  delegate the host and everything under it and are answered with a
  referral. A query for a name that has a CNAME gets the CNAME and, when
  the target is served too, the records of the target.
- An MX value can carry a priority: `10 mail.example.com`.
- Settings per domain: name servers (`ns`), administrator (`admin`), the
  time to live of the records (`ttl`) and the SOA timers (`refresh`,
  `retry`, `expiration`, `minimum`). They are given to `/domain` when the
  domain is added, changed with `update=true`, and saved in the
  configuration file. In the library: the options of
  `NameDB.addDomain()`, `NameDB.setDomainOptions()`, `NameDB.getDomain()`
  and the `updatedomain` event.
- The listen address options take a comma separated list of addresses,
  IPv4 and IPv6. `NameServer` accepts a list or an array.
- `--dns-refuse-out-of-zone` (`refuseOutOfZone` in `NameServer`) answers
  REFUSED to queries for names outside the served domains.

### Changed

- Repository layout: the library is in `lib/`, the program is
  `bin/tr-ddns`. A launcher stays at the old `./tr-ddns` path.
  `require('tr-ddns')` and the old deep paths such as
  `require('tr-ddns/namedb')` keep working through the `exports` map;
  other files of the package can no longer be required.
- `package.json` has a `bin` entry, so installing the package provides the
  `tr-ddns` command.
- `README.MD` is now `README.md`.
- `tr-apisrv` 0.2.0 to 3.0.0, `optist` 2.0.1 to 3.0.0 and `dns2` 2.1.0 to
  3.1.1.
- Errors generated by the HTTP layer itself (unsupported method, unreadable
  body, read timeout) are now JSON in the same `{ status, code, message }`
  envelope as all other API errors. They used to be `text/plain`.
- A request path with an empty segment or a dot segment (`//`, `/.`, `/..`)
  is answered with 400 instead of 404.
- A request body larger than 1 MiB is refused with 413.
- Command line usage errors are printed to the standard error.

- Node.js 24 or newer is required.
- Answers have the AA flag set.
- A query for a name that does not exist in a served domain is answered
  with NXDOMAIN. A name with hosts below it exists.
- Answers without data, NXDOMAIN included, carry the SOA record of the
  domain in the authority section, so that resolvers can cache them.
- A client that uses EDNS gets an OPT record in the answer.
- An underscore is accepted at the start of every label of a name, not
  only the first, and a name may end with a dot.
- `/dump` and the configuration file have the new record types in the
  `data` of every host, as empty arrays when unused.
- A query for a name inside a served domain is answered whatever the query
  type is, with an empty answer when there is no data. Types that the
  server did not know, such as HTTPS (65), used to get no answer at all,
  which made clients wait for a timeout.
- A name inside a served domain that is not a valid host name gets an
  NXDOMAIN answer instead of no answer.
- Packets that are not plain queries are ignored: responses, operations
  other than QUERY, and packets that do not have exactly one question.
- A DNS listener that cannot be started makes `NameServer` emit `error`,
  and the program exits with status 1. The failure used to be silent.
- A missing configuration file is reported as missing.
- The configuration file is written to a temporary file that then
  replaces the old one. Its permissions are kept, and a symbolic link
  stays a link.
- Every record value is validated and stored in a normal form, also when
  it comes from the configuration file or as an array through the
  library. An entry with an unusable value in the configuration file is
  skipped with a warning. IPv4 addresses are stored as dotted quads and MX
  hosts in lower case.
- A TXT value is at most 4096 bytes, and a host has at most 100 values of
  one type.
- The lifetime of a host is no longer limited to about 24.8 days.
- A host that expires advances the serial of its domain.
- The serial of a domain is read from the configuration file and never
  goes backwards over a restart.
- API credentials are checked before the request body is parsed, and
  compared in constant time.
- A request body is at most 64 KiB, a JSON body must be an object, and
  keys named `__proto__`, `constructor` or `prototype` are refused.
- Queries that get no answer are logged only with `--debug`.
- An HTTP listener that cannot be started makes `ApiServer` emit `error`.
  The program still exits with status 1.

### Fixed

- MX records were never returned.
- `merge=true` copied the TXT values of a host into its MX records.
- A TXT value longer than 255 bytes produced a malformed DNS response.
- `/record` with an invalid value answered 400 but still rewrote the host
  and then failed while sending a second response.
- `/record` made an expiring host permanent.
- `/host` with `remove=true` and `mx` is refused like the other
  conflicting combinations.
- Debug output of the whole database on every configuration write, and of
  the host on every `/record` call.
- The examples in the README.
- A query over TCP that gets no answer no longer leaves the connection
  open until the idle timeout; the connection is closed.

## 1.1.1 (2025-05-12)

- Optional HTTP Basic authentication for the API (`--http-api-user`,
  `--http-api-password`).

## 1.1.0 (2025-05-10)

- A host can have several A, AAAA, TXT and MX records. The new `/record`
  API call adds, sets, removes and clears single values.

## 1.0.10 (2025-05-10)

- A host name may start with an underscore.

## 1.0.1 to 1.0.9 (2025-04-06 to 2025-04-07)

- MX records and simplified domain handling.
- `merge` parameter for `/host`.
- Synthesised NS and SOA records for served domains.
- Logging, and less frequent writes of the configuration file.
- Queries for names outside the served domains get no answer.
- `/stats` API call.
- Fixes to host and domain name validation.

## 1.0.0 (2025-04-06)

- Initial release.
