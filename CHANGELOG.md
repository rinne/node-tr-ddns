# Changelog

Every version published to npm, newest first.

## 3.0.0 (unreleased)

### Library

- `ApiCore`: the calls of the API without a transport. `handle()` takes a
  path and parameters and returns a status and a body. `ApiServer` is now
  a layer on top of it and accepts a shared core in its `api` option.

## 2.0.0 (2026-11-14)

Everything since 1.1.1. The command line, the API calls, the
configuration file and the library interface of 1.1.1 keep working;
[the upgrade notes](https://github.com/rinne/node-tr-ddns/blob/main/docs/upgrading.md) describes what behaves
differently.

### Requirements

- Node.js 24 or newer.
- `tr-apisrv` 0.2.0 to 3.0.0, `optist` 2.0.1 to 3.0.0 and `dns2` 2.1.0 to
  3.1.1.

### DNS

- Answers have the AA flag set.
- A query for a name that does not exist in a served domain is answered
  with NXDOMAIN. A name with hosts below it exists.
- Answers without data, NXDOMAIN included, carry the SOA record of the
  domain in the authority section, so that resolvers can cache them.
- A query for a name inside a served domain is answered whatever the query
  type is, with an empty answer when there is no data. Types that the
  server did not know, such as HTTPS (65), used to get no answer at all,
  which made clients wait for a timeout.
- A name inside a served domain that is not a valid host name gets an
  NXDOMAIN answer instead of no answer.
- Packets that are not plain queries are ignored: responses, operations
  other than QUERY, and packets that do not have exactly one question.
- A client that uses EDNS gets an OPT record in the answer.
- Rate limiting per source address (per /64 prefix for IPv6): 500 queries
  per second by default, set with `--dns-rate-limit` or the `rateLimit`
  option of `NameServer`, 0 for no limit. Queries over the limit are
  ignored.
- Record types CNAME, SRV and CAA, and NS records on a host, which
  delegate the host and everything under it and are answered with a
  referral. A query for a name that has a CNAME gets the CNAME and, when
  the target is served too, the records of the target.
- An MX value can carry a priority: `10 mail.example.com`.
- Settings per domain: name servers (`ns`), administrator (`admin`), the
  time to live of the records (`ttl`) and the SOA timers (`refresh`,
  `retry`, `expiration`, `minimum`).
- An underscore is accepted at the start of every label of a name, not
  only the first, and a name may end with a dot.
- The listen address options take a comma separated list of addresses,
  IPv4 and IPv6.
- `--dns-refuse-out-of-zone` answers REFUSED to queries for names outside
  the served domains. Without it they get no answer, as before.
- A host that expires advances the serial of its domain, and the serial
  never goes backwards over a restart.
- Queries that get no answer are logged only at the debug level.

### API

- `/host` accepts several values for a record type, as a repeated
  parameter or a JSON array, and the new record types.
- `/domain` takes the settings of a domain, and `update=true` changes
  them for a domain that is already served.
- `/record` works for every record type.
- `/stats` reports `authFailures` and, under `dns`, counters of queries
  received, answered and dropped by reason.
- The lifetime of a host (`ttl`) is no longer limited to about 24.8 days.
- Every record value is validated and stored in a normal form. IPv4
  addresses are stored as dotted quads and MX hosts in lower case. A TXT
  value is at most 4096 bytes, and a host has at most 100 values of one
  type.
- Errors generated by the HTTP layer itself (unsupported method,
  unreadable body, read timeout) are JSON in the same
  `{ status, code, message }` envelope as all other API errors. They used
  to be `text/plain`.
- A request path with an empty segment or a dot segment (`//`, `/.`,
  `/..`) is answered with 400 instead of 404.
- A request body is at most 64 KiB, a JSON body must be an object, and
  keys named `__proto__`, `constructor` or `prototype` are refused.
- Credentials are checked before the request body is parsed, and compared
  in constant time.
- `/dump` has the new record types in the `data` of every host, as empty
  arrays when unused, and the settings of the domains.

### Program

- Installing the package provides the `tr-ddns` command. The program is
  `bin/tr-ddns`; a launcher stays at the old `./tr-ddns` path.
- The configuration file is written to a temporary file that then
  replaces the old one, so a crash cannot leave half a file behind. Its
  permissions are kept, and a symbolic link stays a link.
- On SIGTERM and SIGINT the pending changes are written to the
  configuration file and the program exits with status 0.
- `--config-write-interval` sets the shortest time between two writes of
  the configuration file.
- A listener that cannot be started ends the program with status 1 and a
  message. A DNS port that was in use used to be ignored silently.
- `--http-api-password-file` reads the API password from a file.
- A warning at startup when the API listens on an address other than
  loopback without authentication. The defaults have not changed.
- `--log-level` selects what is printed: `none`, `error`, `warn`, `info`
  or `debug`. `--debug` is the same as `--log-level=debug`. Errors and
  warnings go to the standard error.
- An entry with an unusable value in the configuration file is skipped
  with a warning at startup.
- A missing configuration file is reported as missing.
- Command line usage errors are printed to the standard error, and
  `--help` lists how options are given in the environment.

### Library

- The library is in `lib/`. `require('tr-ddns')` and the old deep paths
  such as `require('tr-ddns/namedb')` keep working through the `exports`
  map; other files of the package can no longer be required.
- Type declarations (`lib/index.d.ts`).
- `ConfigStore` loads a configuration file into a `NameDB` and saves it
  on changes.
- `NameDB`: `lookup()`, `getDomain()`, `setDomainOptions()`,
  `getHostExpires()`, `close()`, options for `addDomain()`, and the
  `updatedomain` event.
- `NameServer`: `stats()`, the `rateLimit` and `refuseOutOfZone` options,
  lists of listen addresses, an `error` event when a listener cannot be
  started, and `close()` returns a promise.
- `ApiServer`: `close()`, `ready` and `error` events, and the
  `nameServer` and `maxBodySize` options. A listener that cannot be
  started is reported with the `error` event instead of ending the
  process.
- `log` has levels: `log.error()`, `log.warn()`, `log.info()`,
  `log.debug()`, `log.setLevel()` and `log.getLevel()`.

### Fixed

- MX records were never returned.
- `merge=true` copied the TXT values of a host into its MX records.
- A TXT value longer than 255 bytes produced a malformed DNS response.
- `/record` with an invalid value answered 400 but still rewrote the host
  and then failed while sending a second response.
- `/record` made an expiring host permanent.
- `/host` with `remove=true` and `mx` is refused like the other
  conflicting combinations.
- Record values in arrays, from the configuration file or through the
  library, were stored without validation.
- Debug output of the whole database on every configuration write, and of
  the host on every `/record` call.
- A query over TCP that gets no answer no longer leaves the connection
  open until the idle timeout; the connection is closed.

### Project

- A test suite built on `node:test`, run with `npm test`, with a coverage
  threshold. It covers the name database, the DNS server over UDP and
  TCP, the HTTP API, the configuration store, the command line program,
  the contents of the npm package, and the examples in the documentation.
- Documentation in `docs/`, and a rewritten README.
- An allowlist of published files, a lockfile and a CI workflow.
- `README.MD` is now `README.md`.
